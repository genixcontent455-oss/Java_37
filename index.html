University Examination Seating Plan and Hall Ticket Validator

A Java console application that brings candidate registration, department-aware seating, hall-ticket credential checks, examination-centre validation, and attendance reporting into one workflow.

Project ID: 37Java 17+ Standard JDKNo external dependencies Console application
Explore repository README System architecture

The problem

Manual examination-day processes can make seating allocation, identity checks, duplicate admission prevention, and attendance calculation time-consuming and error-prone.

Project objective

Provide a structured, testable Java workflow that registers candidates, separates two configured departments in a checkerboard seating layout where possible, verifies ticket credentials and centres, and reports session attendance.

Core features

The feature set below reflects the Java implementation in this repository.

01

Candidate registration

Validates candidate fields and rejects duplicate university seat numbers.

02

Checkerboard seating

Uses row/column parity to alternate two configured departments across horizontal and vertical neighbours.

03

Hall-ticket validation

Checks credential format, registry membership, SHA-256 hash, and assigned examination centre.

04

Admission control

Blocks duplicate admission, missing enrolment, missing desk assignment, and admission after session closure.

05

Attendance audit

Tracks registered, admitted, and absent candidates separately for each session.

06

Scripted demonstration

Menu option 9 runs a complete example using synthetic candidate data and credentials.

System workflow

A simple flow from candidate entry to the final attendance report.

Register

Create validated Candidate objects and store unique USNs.

Allocate

Fill the hall matrix using the two-department checkerboard algorithm.

Validate & admit

Verify credential and centre before recording an admission.

Finalise

Calculate absentees and produce a session attendance report.

Object-oriented concepts

Concepts demonstrated by the current source code.

Encapsulation

Candidate data is private and exposed through validated methods.

Abstraction & responsibility

Validation, seating, session workflow, and audit logic are separated into classes.

Constructor overloading

SeatingArrangementEngine provides configurable constructors and uses this(...).

Inheritance

Both custom checked exceptions extend Java's Exception class.

Method overriding

Candidate overrides equals(), hashCode(), and toString().

Enums & exceptions

Admission outcomes and invalid-ticket reasons use enums; validation failures use checked and unchecked exceptions.

This application is single-threaded. Multithreading and thread synchronisation are not implemented. The static HTML page is a project presentation page only; it is not a frontend connected to the Java program.
